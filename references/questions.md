# 对话提问与内部覆盖图

本文件是 agent 的内部检查表，不是让用户逐项作答的问卷。先确认目标；需要排查时让用户自由讲述，再抽取事实。完整维权的争议排查只追问会改变争议是否成立或当前签署风险的关键缺口；金额、月数与流水等细节留到测算。仅估算不执行整份覆盖图，只补计算需要的信息。用户已经说过的跳过；“未提到”标未知，不标没有。

## 开场先确认目标与处境

用户尚未说明目的时，先用一次真正点选提问：

> 你这次最想先了解什么？还没被裁、只是想提前算一算，也可以。

- 单位已经提出让我离开，或我已离职，想看看怎么争取权益
- 还没被裁，担心之后会被裁，想先看看有哪些风险
- 暂时不考虑离职，想看看单位有没有侵犯我的权益
- 只想估算一下，离职时能拿多少补偿或赔偿

允许用户直接描述或有多个目标；按其优先目标开始，不要求强制归成一项。用户已说“只算金额”等就直接沿用，不再弹卡片。

本次目标与实际状态分开记录。选择仅估算不代表已经被裁；实际状态和解除情景从用户已有描述提取，不清楚且影响计算时才补问“是单位已经给了离职安排，还是你想提前估算？”未有预计结束日期时询问想按哪个日期估算，不擅用今天作为已解除日。

简短说明对应路径：完整维权说明会分析、测算并整理文书；风险或在职排查说明会先看问题和依据；仅估算可说“那我们先把金额算清楚，了解工作时间、税前收入和你想按哪种离职情况算就好。”随后按需核对身份，不能因用户说“只算”跳过适用范围。

## 从故事确认身份与适用范围

确认目标后，排查路径从故事或材料中提取以下身份；仅估算也核对适用范围。不清楚时才补一次点选，也接受用户直接说：

- 公务员
- 事业编制人员
- 国企、央企的劳动合同制员工
- 私企或其他企业的劳动合同制员工
- 国家机关、事业单位的劳动合同制员工，无编制
- 劳务派遣员工
- 不确定

国家机关或事业单位的劳动合同制人员在本 skill 范围内；公务员、事业编制人事争议暂未覆盖。不确定时仅补关系性质；劳务派遣要区分签约单位、用工单位、退回与解除。身份已在用户叙述中清楚的直接跳过点选。

## 首先请用户讲述

本节用于争议或风险排查。仅估算直接依 assessment.md 收集必要参数，不要求讲一段完整争议经过；风险排查的邀请不预设单位已经通知解聘。

先直接说明这段对话要帮用户分析什么，再邀请其讲述。不说“进入第二步”“像跟朋友讲一样”等流程或语气提示，也不保证能找到对用户有利的结论。可参考：

> 我们可以先聊聊你和单位之间发生了什么，我会帮你看看单位的处理有没有值得核查的问题。你大概什么时候入职、签了几年的合同？现在是你想离职、单位要解聘你，还是合同快到期了？单位给了什么理由和方案？工作期间还有哪些事让你觉得不对，也都可以说说。我会根据你讲的情况，找出可能涉及的争议，再补问判断时真正需要的信息。

用户可以一次写长段、分几条发或只说最紧急的事。合同或通知可在用户提到、或者确实能省去追问时顺势请其上传；不在邀请中堆成清单。不要在这段话后立刻弹出多类卡片。若用户刚开始就提到马上签字，先处理文件和时间压力，再回到其余问题。合同年限可作为用户自由叙述的提示；后续已有合同起止日期时自行推算，不重复追问“几年”。新试跑中尚未收到任何经过时，即使用户说“继续”，也不能借用旧案例事实或启动下表的条件追问；可以简短邀请其讲本次案例，或等待其发送材料。

## 提取与反馈

先在内部做一张状态图：类别｜用户已说的事实｜材料来源｜可能问题｜仍缺的关键事实｜状态（有线索／明确没有／未知／尚未涉及／不适用）。提取后给用户一段短反馈，通常只写最相关的两三项，例如：

> 我先记下：人事口头以考核不合格要求你这周离开，没给补偿，还让你写个人离职申请；你的固定期限合同目前仍在期限内。这里先要看解除依据和待签文件。试用期、工资等我也会按你提到的情况继续核对。

必要时请用户纠正明确的事实错误，不要求逐项确认每个字段。若有矛盾，指出哪两处冲突。将紧急、对结论影响大、用户主动提到的类别排在前面；不要固定照表的排列顺序。

## 下一次提问如何选择

调度依据是已有事实、尚未覆盖的话题和待处理线索，不固定逐题执行。探索与验证的判断规则只在 `assessment.md` 维护。

每次收到回答：更新事实与来源；用户纠正时替换受影响记录；区分单位主张和已知行为；提取新线索。已知类别跳过点选，不依职位名或一个词推断用户未提供的身份，不把“有”扩写成所有子项都有问题。

下一动作按以下优先级选择：

1. 用户当前目标与紧急事项：用户要暂停就暂停；存在紧急签署、适用范围冲突或会推翻当前判断的信息时先处理。
2. 当前话题的关键验证：仅补会改变已发现问题判断的缺口；足够判断即收束这项，金额及证据整理留到后续。
3. 同话题的新线索：建立独立问题；能顺势简短核对就处理，否则登记后转入对应话题，不丢失原问题。
4. 未覆盖的相关方向：用一项概括探索发现是否有线索；没有则换话题，有则转验证，未知或跳过记录状态。不能把探索做成法律要件清单。
5. 排查路径已覆盖相关方向且所有线索已有处理状态：完成内部法律检查，交付争议确认表；完整维权收到核对后才测算。仅排查交付判断和方向即可；仅估算按测算停止条件交付，不执行此覆盖门槛。

无特别优先事项时，按解除情形、合同签订、试用期、特殊保护、社保、工资待遇、工时加班、休假、调岗施压、附加限制推进。这是导航顺序，不是要求用户完整作答的题序。

一个话题一次简短转换说明，例如“接着看看社保有没有漏缴”。同一话题有多条问题时分别收束；不把找到一个问题当作整类结束。每次一般一个问题或同话题的小组，不同时发多个类别。必要时简短说明已处理的话题和剩下范围，不对每个“没有”重复总结。

短状态用点选：身份、合同类型／签约次数（未知时）、试用期发薪比例、特殊保护、社保起缴与足额、加班休假、调岗施压、入职告知与附加限制。时间、工作经过、考核、工资奖金等开放内容用对话。控件发出后等待提交，不马上结束回复；使用 `request_user_input_async` 时随后用 `clock.sleep` 等待，每次不超过六十秒，用户提交后再处理回答，不把等待超时当成答案。控件失效重发该题，不推断用户已回答。宿主只支持单选时提供“不止一项”自由填写，无控件时改普通对话。

## 问题覆盖与条件补问

下表是内部覆盖图。每类未涉及且相关时做概括探索；有线索才补决定性事实。合同、通知等材料先提取，用户已有回答不重复。细节多少取决于判断需要，不取决于表格有多少字段。

| 类别 | 自由叙述中提取 | 必要时才补的关键事实与判断用途 |
| --- | --- | --- |
| 当前离职情况与待签文件 | 当前是听说、已通知、在谈、到期或已离职；公司给出的理由、方案、签字与离开时间；文件标题和内容 | 仅在本次讲述出现相应线索且会改变判断时补问。理由不明才问理由；用户提到文件且其内容影响解除性质时，先请其概括，方便时可上传。要求“个人原因辞职”时确认是否真由用户自愿提出、是否已签；提到考核不合格时，同时检查制度来源与制定程序、告知时间、指标对应的期间、评分与事实依据，再核对是否培训或调岗；提到违纪才问具体行为和制度；提到经营变化才问单位具体说明。先识别员工主动离职、单位针对个人解除、经济性裁员、合同到期不续签或其他终止，再走对应分支，不能给所有路径套同一个 N／N+1／2N。实际已经解除或终止时再核对离职证明及档案社保转移；仅在谈判时不问后续手续。目的：分清实际发生的行为和可能的解除路径。 |
| 合同签订与期限 | 实际入职日、首份合同是否在入职后一个月内签、固定／无固定／任务期限、起止日期、续签史、签约主体、工作城市、合同是否交付本人 | 合同照片有日期就直接读取；没有材料不逼用户回忆精确签字日，问是否一个月内签。实际开始工作与签约时点分开记录；判断是否及时签约只需确认是否在入职一个月内签好，不能因合同起始日与入职日相同就推定实际签约及时。是否续签过或属于第一份合同应从材料或一次简短澄清确定。固定期限由日期推算几年；到期不续签才补双方续签意愿及新旧条件。目的：判断未及时签约、无固定期限及到期情形。 |
| 试用期 | 合同期限、约定试用月数、试用期工资是全额、约 80% 或其他；是否延长或重复约定 | 合同显示未约定且用户未提到实际试用时，记录没有合同约定的试用期；约定与实际安排都未知时，用一句话确认合同是否约定试用期。出现单位实际安排试用或以试用不合格解聘的线索时，即使合同空白也继续核对。发薪方式用点选“全额／80%／其他（填写）／不清楚”；80%不能单独作为合规结论，工资标准在第三步核对正常约定工资、同岗标准及最低工资。超过约定上限需核实实际履行期间，不能只拿约定直接计算赔偿。目的：判断期限及发薪问题。 |
| 特殊保护 | 孕产哺乳、工伤或职业病、疑似职业病观察、医疗期、连续工作满十五年且距退休不足五年、职业危害及离岗检查 | 用户未提及时，用一次点选呈现“都没有／孕产哺乳／工伤或职业病／医疗期／满十五年且距退休不足五年／职业危害离岗未体检／不止一项”。若尚未解除，问题说“单位提出解聘时”，不说“解除劳动合同时”。宿主若只支持单选，用户有多项时选择“不止一项”并自由填写；不得假装单选是原生多选。有线索才深入时间、认定和材料。目的：核验解除限制；不把普通疾病自动当成法定医疗期。 |
| 社保 | 是否缴纳、从何时开始、入职前几个月及试用期是否漏缴、是否足额、中间有无断缴、缴费单位与记录 | 用户未提及时，先用点选问“入职当月开始／转正后开始／入职一段时间后开始／一直没缴／不清楚”，再对已缴者用另一项点选问“足额／按最低缴费基数缴纳／其他基数或比例不足／不清楚”；是否存在中途断缴未知时另作简短核对。一直未缴者跳过足额题；不要把时间与基数塞进同一题。出现晚缴、断缴或不足额时才对话补充事实与记录；按最低缴费基数缴纳只记为线索，结合实际工资、适用基数上下限及地区规则核验，不能直接判违法。公积金仅用户主动提出时另行分析。目的：核验社保履行及相关独立请求。 |
| 工资、绩效、奖金和提成 | 拖欠、扣款、降薪、未发绩效奖金、约定发放周期；实际工资是否可能低于当地最低工资 | 用户已说明有未发项目时，先记为潜在欠付；只在到期与否不清且会影响判断时问原定发放时间或条件。基本工资、当期绩效、学年绩效和补贴可先按性质分开记录，不在此时追逐月流水、缺发月数和具体金额。低于最低工资不能要求用户凭记忆判断：第三步拿到工作地、工资口径与官方最低工资后主动比对，必要时回补第二步争议清单。目的：识别欠付、扣薪、违规降薪和低于最低工资；金额留到第三步。 |
| 工作时间、加班与加班费 | 合同或单位规定的工时与实际是否一致、工时制度及其依据；工作日延时、休息日、法定节假日，是否由单位安排或认可、补休和已支付情况 | 未涉及先一次点选“有加班，没拿到加班费／有加班，给过加班费或补休／没有加班／不清楚”。约定与实际工时、工时制度尚未知且影响判断时，用对话补问正常安排和实际安排，不要求用户先自行判断是否合理。第二项只记录已经给过补偿，不能因此认定足额或合规；有必要时再问属于哪种加班及如何处理，不先追小时数和金额。问题若问的是“是否有未付加班费”，用户答没有只能记为没有已知未付线索，不能扩写成从未加班。目的：识别工时安排、加班程序和未付或少付加班费；即使已付加班费，也不据此排除工时违法。 |
| 休假 | 年假应休已休、未休原因、是否已支付，法定节假日安排，是否被要求放弃休假或因休假扣薪 | 未涉及先一次点选“都没有／未休年假或未付年假工资／法定节假日未依法安排／被要求放弃休假或休假扣薪／不止一项／不清楚”；点到有时再问休假类型、是否由单位安排及有无支付，不先追具体天数或金额。目的：识别休假争议；计算留到第三步，年假按 legal-sources.md 登记的官方补充规则；其他规则仍不足时标明缺口。 |
| 调岗、待岗与施压 | 降薪、调地点、停工停号、罚款扣证件或押金、危险作业、威胁、逼写个人辞职 | 用户已讲出的行为按关键缺口补问；未提到时，用一次点选呈现“都没有／未经同意调岗或降薪／待岗或停工／罚款扣证件押金／威胁逼离职／强迫劳动或危险作业／不止一项”，有线索再对话了解经过，不逐项卡片。目的：弄清是用户自愿离开，还是单位采取了改变条件和施压的行为。 |
| 入职告知与合同附加限制 | 入职前告知的工作内容、地点或条件是否与实际明显不符；是否有培训服务期、竞业限制、要求员工付违约金等条款 | 自由叙述未涉及时用一次点选筛查“都没有／入职前告知与实际明显不符／合同或协议要求我付违约金／签过服务期或竞业限制协议／不止一项／不清楚”。点到有才读合同、招聘信息或协议，核对签约与实际履行。目的：覆盖原 Project 的未如实告知、违法违约金和竞业限制线索；不能因为出现条款就自动断言无效或应赔偿。 |
| 离职结算（条件分支） | 最后工资、经济补偿、离职证明、档案和社保转移 | 仅在劳动关系实际解除／终止或单位明确提出结算安排时开启。先核对是否已支付、是否出具证明和办理转移，不能对尚在谈判的用户提前判定这类义务已违反。 |

核心类别为当前离职情况、合同签订与期限、试用期、特殊保护、社保、工资绩效、工时加班、休假、调岗降薪／施压、入职告知与合同附加限制。第二步收束前，对本次叙述未涉及且相关的核心类别做概括排查；用户明确回答没有才记为无，表示不清楚或跳过则记为未核查。以自然话题逐类切换，必要时给简短进度提示；不要连续弹选择卡片或追金额细节。某一问题达到 assessment.md 的判断停止条件，只结束该问题的补问；同类别的独立线索仍分别处理。用户不记得或表示先跳过时保留具体缺口，不为了填满表格要求再答。项目原有的集中裁员人数、家庭负担和后续招聘按用户此前取舍不主动问，用户自述时记录并核验，但不宣称完成全面经济性裁员审查，也不宣称第二步穷尽全部劳动争议。

## 考核与解除：独立检查制度依据

“单位说考核不合格”只记录单位主张，不默认用户确实不合格。依次核对：

- 制度：指标何时制定、是否适用于被考核期间、是否经过适用的民主制定和协商程序、何时公示或告知。读取《中华人民共和国劳动合同法》第四条第二款、第四款，以及《最高人民法院关于审理劳动争议案件适用法律问题的解释（一）》第五十条第一款。第四条没有统一要求公示满多少天，不能编造固定天数，也不能将“职工代表大会或者全体职工讨论”误写为必须工会代表大会批准。
- 事实：单位以哪些实际行为认定不合格，是否有评分或证据，要求次日提交大量材料等安排是否造成无法证明既有工作的情况。晚告知是争议线索，不能仅凭提前一天就认定单位未履行全部民主程序。依据解释（一）第四十四条核对单位对辞退决定的举证责任。
- 解除：从单位给出的实际理由匹配《中华人民共和国劳动合同法》第三十六条、第三十九条、第四十条或第四十一条的相应路径，区别第四十四条终止；检查法定条件与程序是否满足。只对有线索的路径补问，不让用户逐项勾选整部法律。单位给出的解除理由不符合对应条件时，明确指出该理由不能支持解除；不得凭无关路径未问过就默认解除合法，也不能替单位虚构其他理由。

该类别已有潜在问题即停止向用户追无关细节，但必须完成 assessment.md 的事件分析链；关于未知制定程序，交付判断前只补一句具体问题或指出应要求单位提供的材料，不将未提到当成未履行。法条内容和单位现状的对应必须写清。

## 合同分支的三个关键判断

从故事或合同材料中提取，缺失才补问：

- 当前合同类型：固定期限、无固定期限或其他。用户明确说签了三年可记录为固定期限线索；取得合同后核对，不重复询问已清楚的年限。无法区分时用点选。
- 合同历史：第一份、第二份、第三份或更多、不清楚。首签已明确则结束；只说“续签过”尚不足时，补问此前签过几份、是否连续以及是否同一签约主体，只有影响具体判断的事实才继续核实。不能把“续签合同”作为与“第二份”互斥的类型，也不能单凭签约次数直接判断无固定期限义务。
- 当前处理路径：合同期内单位要求解除、合同到期不续签、员工主动离职、协商解除或其他。区分用户说的“裁员”与单位实际处理行为，不要求用户自行选择专业法律路径；故事能判断就反馈当前理解，含糊时点选实际情况。最终法律性质依据事实及条文判断。

合同类型、签约次数和处理路径在内部明确记录来源；出现矛盾或影响当前理解时再简短反馈，不逐字段确认。三项已清楚就不再问；不得因为没有再次弹选项就视为漏查。尚不清楚时不能悄悄推定已确认。

## 清单外问题与停止条件

常见类别和原 Project 是覆盖底线，不是封闭目录。故事、材料和每次回答中的清单外线索，同样进入争议记录；是否违法须对照法律条件。按 `assessment.md` 的探索、验证、新线索处理和事件分析链执行，不在本文件另设一套停止标准。

已知事实足够支持当前问题判断，就停止该问题的补问；单纯的金额、月数及材料整理缺口登记后补。仍需改变结论的关键事实不能跳过，也不要求用户证明其不知道的单位内部程序。用户插入问题先简短回应，再回到其当前目标或未覆盖话题。

紧急、同话题和其他新线索按前面的优先级调度；对每条问题分别收束。不能因为开放叙述而漏掉原有覆盖，也不能因开放发现而无限追问。用户明确缩小范围或跳过时尊重其选择，说明具体未查部分，不保证穷尽全部违法。

## 收束检查

本节及下节用于完整维权或用户选定范围的排查，不用于仅估算。仅排查交付问题和方向即可，用户另要金额再继续。完整维权交付争议确认表之前，在内部逐项核对；确认表经用户核对后才进入费用测算：

1. 用工身份和本案实际离职路径已确定；区分拟解除、已解除和协商中，不仅靠文件标题判断。
2. 合同签约、期限、实际入职及是否续签有信息支持；精确结束日期等计算参数可留到第三步。不能把“签约日已说”写成“实际入职日已说”。
3. 试用期、特殊保护、社保、工资、加班、休假、调岗待岗／施压、入职告知与附加限制，各有本次回答或材料；若跳过，明确列为未核查。
4. 原 Project 对照中的本案条件分支已核对。不适用分支标理由，例如当前合同未到期，便不启动到期续签分支；尚未离职，便不认定离职证明义务逾期。
5. 问过的宽泛问题是否真的覆盖所需事实。用户对“工资有没有问题”答有，不代表已经排除了扣薪或其他欠付；用户对“未付加班费”答没有，不代表从未加班。
6. 对每个命中事件，assessment.md 的依据、事实证据、程序和后果检查已完成或有具体缺口说明；清单外新线索已记录并处理或明确待核实；最低工资等仍依赖第三步数据的检查列为待完成；不因此多问金额，也不宣称已经发现或排除全部违法。

任何核心类别尚未涉及且用户未表示跳过，继续相应话题，不进入工资核算。达到上述条件后，先交付争议表请用户核对；尚不能提示立即测算。用户核对或明确继续后再过渡，具体缺口保留，不说“所有情形都已覆盖”。

## 第二步收束与第三步过渡

只有核心类别已覆盖或用户明确跳过后，交付三列表“问题｜用户现状｜判断及具体法律依据”。现状忠实列出用户提供的合同约定、实际行为和时间，不把单位主张改写为合同约定；例如“合同试用期空白，单位声称一年”不能写成“合同规定一年”。判断说明哪些事实符合或不符合具体条、款、项及其条件；引用相关文字，能形成判断就给结论，而不是所有项目都写待核实。尚未成立的未来欠付、当前未发现违法和确实缺关键条件的项目明确区分。

法律查找、条件核验、官方标准查询和计算由 agent 完成。用户只提供其掌握的事实或材料；不能写“你去核对司法解释／当地标准”。缺信息时直接问具体事实，不反复解释查询、核算由谁承担。能下判断的项目直接写法律要求、单位事实和结论，不把所有结论降格成可能性；依据不足的线索保留，不虚构事实或迁就用户错误法律前提。

表格交付后请用户核对现状、纠正事实并补必要缺口。此处停下来等待回复，不在同一条回复转入工资测算；用户核对或明确继续后才说“接下来核算你可以要求的补偿费用，并整理成文档”。收到纠正时更新表格和受影响判断。

第二步可补少量判断所必需的数据，例如判断社保足额需要的工作地区、实际缴费基数及适用口径的缴费工资；不能用“工资高于最低工资”替代缴费基数核验。不要求用户自行查当地法律标准，官方标准由 agent 查询。前述规则不意味着提前展开赔偿金额或逐月流水。

第三步才收集近十二个月税前应发工资总额或已有月平均数、实际工作月份、奖金绩效是否已包含，以及欠发项目的期间、月数和金额；不用让用户逐月输入十二笔。按已发现项目补必需参数。拿到新数据后若出现新的争议判断，返回更新并核对争议表。三份指定法源及已登记允许的官方补充仍不足以支持金额算法的项目，列明具体法源缺口，不强行算金额。每个项目说明方式、适用理由、法条原文和公式；沿用第二部分加班休假回答，不重复从有无开始问。
