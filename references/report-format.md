# 交给单位的诉求文书：格式与行文约定

本规范仅在需要给单位的诉求文书时读取和执行。仅估算或仅排查默认聊天交付，不因本规范存在而自动生成 Word。

## 两种交付的角度必须分开

聊天中的分析与核对表面向劳动者，用来解释问题、判断、费用和选择。Word 面向用人单位，由劳动者以“本人”的身份直接陈述争议、引用条款、提出请求。不得把聊天分析稿、三列确认表或谈判建议直接搬入 Word。

交付后的文书使用提醒、签字与出勤建议、证据保留、情绪安慰及失业支持入口，依 assessment.md 的“交付后的收尾”在聊天中提供，不增加为 Word 的第四部分。

Word 不写“现状：”“判断：”“建议：”“用户”“skill”“本次测试”“已排除项目”等分析标签；不向单位展示劳动者的协商底价、退让方案、内部核算过程或假设实验。未确定的事实不写成既成违法；可以转化成要求单位提供材料、说明依据的具体请求。已知问题明确陈述，无须在每项下解释 AI 尚未做什么。

## 参照文件是格式与结构的控制源

包内 [通用格式模板](../assets/report-template.docx)，相对 skill 根目录为 `assets/report-template.docx`。此模板保留原样例的页面、主题、样式、编号及 78 个段落角色，以通用占位文字替换原正文；不含原案例事实、个人姓名、图片或元数据。占位文字仅供脚本识别和克隆格式，不能进入最终个案文书。

模板 SHA-256：`6d83c00f23fd756c9d808f8c04cff276a7d3021d54a96d06f316d42bb71b13f4`。模板角色索引由脚本核验；变更时须同步更新生成器并重新验证。

严格复用其标题顺序、编号层级及正文格式；法条按用户后续要求使用下述独立引用样式。样例中的个人姓名、合同条款、照片、日期、数值、法律判断不是新案例事实和法源；法律条号必须重新从指定原文核验，不复制样例的错号。

### 通用框架与个案内容

硬约束为：三部分结构、劳动者向单位提出请求的口吻、先陈述问题或诉求再列相应条款、逐项关联、法条准确引用、真实参数和可复算金额、正文与引用样式区分。

身份、合同期限、试用期、考核、社保、竞业限制、解除类型、费用项目、问题数量和金额均是个案变量。没有发生的争议不写；未成立的请求不写；真实发现的新争议可增加。不得固定输出试跑的七个问题、五项诉求、2N、三年合同或事业单位身份。来源优先级和事实缺口规则对所有案例相同。

已从原 DOCX 核验：

- A4 纵向，单节，页边距上／下 1440 twips、左／右 1800 twips；无表格、无页眉页脚内容。
- 总标题居中 16 磅；原文件标题为“关于解除劳动合同的相关诉求和法律依据”。
- 三个大标题依次为“适用法律条例”“相关争议问题及条例”“本人诉求及相关条例依据”，复用源一级标题样式、22 磅加粗、原自动中文编号、段前段后及行距。
- 普通正文 10.5 磅；源主题的简体中文字体为宋体。问题小标题是同字号宋体加粗，并非另换黑体。源文档没有独立黑体文字角色，不凭印象添加。
- 段落复用源文件的 1.5 倍行距、段前段后、缩进和网格属性，不擅改固定行距。问题小标题、分项诉求、最终赔偿结果加粗；一般说明、一般算式、法条正文不整段加粗。计算明细中的关键收入与结果复用源文件的黄色高亮；法条的关键限制条件可以局部加粗，保持文字可检索。
- 问题小标题与其后第一段正文保持同页，避免页末只有标题；法律文件名称与其链接也保持同页。只为维持这些配对增加“与下段同页”，不改字号、缩进及行距。落款复用源提出人、日期的段落与缩进；末尾是法律文件名称及官方原地址。没有新证据时不复制旧证据图片，也不留空白图片位置。

### 法条引用的独立样式（用户明确要求的格式调整）

- 正文和诉求仍保留源文件 10.5 磅、原缩进和行距。
- `LegalCitation`：宋体 9.5 磅、加粗、深灰 404040、浅灰底色 EDEDED、左右各缩进 420 twips、首行不另缩进、1.25 倍行距、段前 100／段后 40 twips；与下段原文同页。导语保留正体，便于快速识别法律名称与条号。
- `LegalQuote`：宋体 9.5 磅、斜体、深灰 404040、浅灰底色 EDEDED、相同左右缩进、1.25 倍行距、段后 100 twips；不对齐文档网格。只对与本案有关的限制条件局部加粗。正文解释不能混入引号假装法律原文。
- 底色使用段落底纹，覆盖引用区域；不使用文字高亮模拟底色，不把引用变成图片或表格。这一样式适用于所有个案的法条引用。
- 引用正文同时在样式与文字片段中设置斜体，避免不同 Word 渲染器对继承样式的处理不一致。
- 引用不使用表格、截图、卡片或大段全粗；原文可编辑、可复制。只添加这两个命名样式，其他源样式和页面设置保留。
- 引用导语写“法律依据（支持：[具体事项]）：《[法律全名]》第[条／款／项]规定：”，紧接相关原文。`basis_for` 必须指出具体问题、请求或计算规则，不能只写“上述内容”“相关法律”。

## 正文逻辑

### 适用法律条例

先陈述本人的真实劳动关系、合同性质及期限，再列直接支持法律适用的具体条款与原文，最后写“故本人与单位之间的本次劳动合同争议适用……”等简短结论。若已读到本人的合同有关法律适用的条款，可先引用；未提供合同则不得借用样例合同第二十一条、第二十八条。

不在这一部分写报告用途、金额摘要、测试说明、内部法源检索策略或向劳动者解释不同选择。

### 相关争议问题及条例

按样例分别列加粗问题小标题，下面写编号短段；先写本人的具体事实、单位的问题和异议，再列支持这一点的法律全名、条／款／项及原文。每个法律组有明确 `basis_for`。可在引用后补一句事实与法律的对照，但不能只贴一堆法条，也不能改成“事实／现状／判断／依据”四栏模板。

通用顺序为：[问题标题] → [本案行为、事实及异议] → [法律依据及其支持的具体事项] → [相关原文]。一个问题涉及多个独立义务时拆成短段，每段后跟其对应条款。

考核争议分别列制度形成与公示告知、评分事实和举证、解除条件及程序；不因为法条已在聊天中说明就省略。没有证据证明的制度内部程序，转成请单位提供民主程序及告知材料，不编造“从未开职代会”。

一个问题下只放与之直接相关的法条，保留限制条件；长条标“节选”。不单独堆一个法条大全。尚未发生的奖金拒付、竞业欠付等不当作已经违法；确需处理的内容在第三部分写结算或明确安排请求。没有问题的筛查结果和局部假设不进入正式文书。

### 本人诉求及相关条例依据

先写本人要求单位做什么及请求金额，再列支撑该请求的具体条款。各个计算分项先写本案参数或采用的规则，再附支持该分项的条款和原文，紧跟算式和结果；不要把全部测算条款堆在主要诉求下方。按本案实际成立的请求动态生成加粗分项，不以计薪参数或多个赔偿方案开头。

每笔请求应有完整法律名称、相关条文原文、真实期间和参数、可复算公式、结果；即使同一条款已在争议部分出现，诉求下面仍列相关原文，不让单位翻到其他部分才能找到依据。涉及平均工资时紧跟主要赔偿请求列收入构成、绩效、津贴等明细，再给明确结果。普通算式不全部加粗，主要诉求与最终金额重点加粗。

聊天可以分析 N、N+1、2N 的备选情况；正式文书写用户确认的主张。不能把协商底价或“至少 N+1”送给单位；不同请求互斥时不得直接相加。仅缺个别金额的真实权利，可写要求单位核对结算明细，不虚构费用。社保更正与补缴作为履行请求，不计入直接给劳动者的现金总额。

年假等用户局部假设不自动转成实际诉求。须成为已确认案例事实后才写入对外文书。事实不足以支持主张时留在聊天核对，不在 Word 中展开试验。

最后按样例要求单位当面和书面答复，写提出人和时间；未提供姓名用“劳动者”，不借用样例姓名。末尾列实际引用法律原地址，不写本地路径、Markdown、工具名称或“由我核验”。

## 执行与校验

1. 宿主有 documents skill 时使用它和工作区依赖加载器返回的运行环境；其他宿主使用已可用的 Python 与文档工具。格式脚本依赖 Python 3.10+ 和 lxml；不自动安装全局依赖。包内模板只读，缺少渲染能力时报告未完成视觉验证，不宣称格式已实测。临时记录放在任务工作目录。
2. 更新已有个案 DOCX，不创建并存的相近报告。脚本 `scripts/build_report.py` 从源包复制正文段落／文字格式，新增通用法律引用样式；输入为审核后的 JSON，三个 sections 的标题必须与源文档完全一致，问题与诉求数量不受试跑案例限制。脚本只排版，不承担法律推断与计算。
3. 段落角色直接克隆源标题、问题小标题、普通正文、编号短段、分项诉求、局部加粗、结果和落款格式。支持 text、bold_spans、highlight_spans 作局部强调；官方地址使用源超链接文字样式并建立实际链接，不统一换字体、字号、行距或编号。
4. 依宿主文档工具的要求登记 create／edit 操作；用任务局部字体映射解决缺字，不修改模板、系统配置或全局字体。字体没有斜体字面时，在任务局部渲染配置中加载可用的合成斜体规则；不能只检查 XML 标志而漏看实际显示。渲染输出并逐页检查，必要时对照模板的页面和样式。
5. 每个 `law_heading` 填 `basis_for`；每段 `quote` 紧跟对应 `law_heading`。逐项核对先问题或诉求后引用、条款支持事项和具体正文一致，区域规则也拆分导语与准确原文；无分析标签、无聊天建议、无假设案例指控、无对单位披露的协商底价。其他身份与争议组合也必须能按该框架生成，不带入试跑参数。
6. 复算金额，检查法律引文和限制条件、样例个人数据已移除、原文件 SHA-256 未变、页面和样式保存。完成后仅交付可编辑 DOCX。
